# DarkTechMD — план читалки Markdown на Rust

> Документ-задание. Self-contained: исполнять можно в новом чате без контекста этой
> переписки. Обсуждение и правки — до старта выполнения.

## 1. Цель и принципы

Читалка Markdown **DarkTechMD** — быстрая замена MarkMello (Avalonia), которая не
зависает на больших файлах. Укажи автора - Dark Wizard. И сайт https://darktech.ru

Принципы, по приоритету:

1. **Производительность важнее фич.** Файл 50 МБ открывается без фризов, скролл
   никогда не дёргается. Всё, что мешает этому, вырезается.
2. **Только чтение.** Редактирования нет вообще. Сети нет вообще (картинки только
   локальные, автообновлений нет).
3. **Один exe.** Без установщика, без внешних рантаймов, статический CRT.
4. **Управление и опции — 1 в 1 к MarkMello** (список ниже), внешний вид — «дух 1 в 1»:
   тот же минималистичный ридер, те же пропорции и панель настроек.

Решения, уже принятые с владельцем (не пересматривать без обсуждения):

- GUI: **egui/eframe** (immediate mode, полный контроль виртуализации текста).
- Markdown-парсер: **pulldown-cmark**.
- Mermaid-диаграммы и встроенный HTML в v1 **не рендерятся** — показываются как
  кодовые блоки (значок/подпись «diagram/html»).
- Картинки: только локальные пути (относительно файла и абсолютные).

## 2. Почему MarkMello зависает — и почему здесь этого не будет

MarkMello (Avalonia) строит визуальное дерево **всего** документа: 10 МБ markdown =
десятки тысяч контролов, отсюда фризы при открытии и скролле.

DarkTechMD рендерит **только видимое окно ± overscan**:

- Документ — вектор «блоков» (заголовок, абзац, элемент списка, строка таблицы,
  строка кода, картинка, разделитель, цитата). Блоки не знают про экран.
- Раскладка блока в текстовый `Galley` кэшируется по ключу
  `(block_id, width, font, size, line_height, theme)`. При скролле ничего нового
  не считается, кроме вновь появляющихся блоков.
- Высота неизмеренных блоков — оценка (`символов / символов_в_строке`), позиция
  скроллбара уточняется по мере измерения. Стандартный подход виртуализированных
  списков.
- Парсинг и первичная индексация — в фоновом потоке; UI показывает первые блоки,
  не дожидаясь конца файла (для гигантских файлов — стриминговый парсинг чанками).

## 3. Стек и обоснование

| Компонент | Выбор | Почему |
|---|---|---|
| GUI | `eframe`/`egui` (последняя стабильная) | immediate mode = никаких скрытых layout-проходов по всему документу; мгновенный старт; один exe |
| Парсер MD | `pulldown-cmark` (с таблицами, task list, strikethrough) | самый быстрый зрелый парсер, стриминговый API идеально ложится на блочную модель |
| Подсветка кода | `syntect` (дефолтные подсхемы, lazy загрузка) | зрелый, без сети; если раздует exe — вынести в feature, дефолт off |
| Картинки | `image` (png/jpg/gif/webp/bmp) + `usvg`+`tiny-skia` для SVG | только локальные; декод в фоне в текстуру, кэш LRU по пути+mtime |
| Настройки | `serde` + `serde_json` | как у MarkMello, файл `settings.json` |
| Файловый watcher | `notify` | перечитать файл при изменении на диске (debounce 300 мс) |
| Shell-операции | `open` crate, `rfd` (диалог выбора файла) | открыть ссылку в браузере / диалог Ctrl+O |
| Шрифты | встроить в exe: Noto Serif, Inter, JetBrains Mono (все + кириллица, лицензии OFL в `assets/fonts/`) | ноль внешних зависимостей; MarkMello-триада Serif/Sans/Mono |

Сборка одного exe (Windows, win-x64):

```toml
# .cargo/config.toml
[build]
target = "x86_64-pc-windows-msvc"
[rust]
# статический CRT — не нужен vcredist
rustflags = ["-C", "target-feature=+crt-static"]
```

`cargo build --release` → один `DarkTechMD.exe`, ожидаемый размер 10–15 МБ.
Иконка и метаданные через `winres`.

## 4. Функциональность v1

### 4.1 Открытие документа
- Аргумент CLI: `DarkTechMD.exe path\to\file.md` (несколько путей — несколько вкладок).
- Drag&drop файла в окно; диалог `Ctrl+O`.
- Ошибка чтения — экран с сообщением (не падать).
- BOM (UTF-8 BOM) и CRLF/LF — корректно. Нелатинские пути — корректно.

### 4.2 Рендер Markdown (поддерживаемое)
- Заголовки h1–h6 с якорями; абзацы; **жирный**, *курсив*, `код`, ~~зачёркнутый~~,
  [ссылки](…), автоссылки; списки (вложенные, task list с чекбоксами-глифами);
  цитаты (в т.ч. «alerts» `> [!NOTE]/[!WARNING]/…` — цветная полоса и иконка);
  таблицы (с выравниванием); блоки кода с подсветкой и кнопкой «копировать»;
  разделители `---`; горизонтальная прокрутка широких блоков (код/таблицы);
  локальные картинки с ленивой загрузкой и рамкой при ошибке.
- Не рендерим: Mermaid (блок кода с подписью), встроенный HTML (показываем как
  исходник в приглушённом виде), footnote-хождение (текст рендерим, ссылок-сносок нет).

### 4.3 Ссылки
- `http(s)` — клик: открыть в системном браузере; правый клик: «копировать адрес».
  Подсказка с URL при наведении.
- Локальный `.md` (абсолютный или относительно файла) — открыть новой вкладкой.
- Локальный другой файл — shell-open.

### 4.4 Выделение и копирование
- Выделение мышью (в т.ч. через несколько блоков), двойной клик — слово,
  тройной — абзац. `Ctrl+A` — весь документ (виртуально, без раскладки).
- `Ctrl+C` — выделенный текст как plain text. Копирование как Markdown/
  Telegram-Markdown — вне скоупа v1 (запомнить на потом).
- Правый клик — контекстное меню: Копировать / Выделить всё / (на ссылке) Копировать адрес.

### 4.5 Поиск (Ctrl+F)
- Инкрементальный поиск по исходному тексту (`memchr`/`aho-corasick` по блокам в фоне).
- Панель сверху: поле, счётчик `3/17`, Enter/Shift+Enter — вперёд/назад, Escape — закрыть.
- Подсветка попаданий в видимом тексте; автоскролл к текущему попаданию.

### 4.6 Панели
- **Оглавление (слева, опционально):** из заголовков h1–h6; клик — скролл к разделу;
  текущий раздел подсвечен по позиции скролла; настройки (сторона, макс. уровень,
  свёрнутость уровней) — как в MarkMello.
- **Миникарта (справа, опционально):** «скелет» документа — полоски-блоки
  (заголовки плотнее и ярче, код — монотонные строки, картинки — прямоугольники).
  Не рендерим текст в миниатюру — O(высота миникарты), не O(документ).
  Прямоугольник вьюпорта, клик/драг — навигация.

### 4.7 Вкладки и сессия
- Таб-стрип сверху (как MarkMello): имя файла, крестик, Ctrl+Tab / Ctrl+Shift+Tab,
  Ctrl+W. Заголовок окна = имя файла.
- Сессия: открытые вкладки и позиция скролла каждой — сохранять в settings.json,
  восстанавливать при старте (позиции — после фоновой раскладки, без прыжков).
- Welcome-экран при запуске без файлов: логотип, «Открыть файл…», последние файлы.

### 4.8 Watcher
- Файл изменился на диске → перечитать (debounce 300 мс), сохранить позицию скролла
  по якорю ближайшего блока. Файл удалён — баннер «файл недоступен».

### 4.9 Настройки (панель, 1 в 1 набор MarkMello)
Панель настроек чтения (та же композиция: строки «подпись + сегментированные
плашки / слайдер», стили — свои, но по той же сетке):

| Опция | Значения | Дефолт |
|---|---|---|
| Тема | Светлая / Тёмная / Системная | Системная |
| Шрифт документа | Serif / Sans / Mono | Serif |
| Размер шрифта | 14–24 px | 18 |
| Межстрочный интервал | 1.40–2.00 (шаг 0.05) | 1.7 |
| Ширина текста | Узкая 640 / Средняя 820 / Широкая 1080 (+ произвольная 640–1280, шаг 20) | Средняя |
| Межбуквенный интервал | 0–2 (шаг 0.1) | 0 |
| Размер шрифта интерфейса | 11–18 px | 14 |
| Миникарта | Авто / Вкл / Выкл | Авто |
| Оглавление: сторона | Слева / Справа | Слева |
| Оглавление: макс. уровень | H1–H6 | H6 |
| Оглавление: интервал строк | 1.2–2.0 | — |
| Оглавление: размер по уровням | по слайдеру на уровень | — |
| Язык интерфейса | Русский / English / Системный | Системный |
| «Сбросить настройки» | — | — |

Плюс поведение окна: позиция/размер/развёрнутость — сохранять.

Хранение: `%APPDATA%\DarkTechMD\settings.json` (структура полей — camelCase, как
у MarkMello). Повреждённый файл → безопасные дефолты, молча.

**Что из MarkMello НЕ переносим** (осознанно): редактор и quick edit, ассоциация
файлов через установщик, автообновления, окно настроек обновлений, режимы рамки
окна (обычное окно ОС), миникарта-фотография документа (заменена скелетом).

### 4.10 Горячие клавиши
`Ctrl+O` открыть · `Ctrl+F` поиск · `F3`/`Shift+F3` поиск далее/назад · `Esc`
закрыть поиск/снять выделение · `Ctrl+A` выделить всё · `Ctrl+C` копировать ·
`Ctrl+Tab`/`Ctrl+Shift+Tab` вкладки · `Ctrl+W` закрыть вкладку ·
`Ctrl+=`/`Ctrl+-`/`Ctrl+0` размер шрифта (в дополнение к слайдеру) ·
`Ctrl+1..3` ширина текста.

### 4.11 Локализация
RU + EN, словарь ключей по образцу MarkMello (`i18n.rs`: `HashMap<Lang, HashMap<&str, &str>>`),
переключение без перезапуска. Все строки UI — только через словарь.

## 5. Внешний вид

- Раскладка главного окна MarkMello: титульная строка со вкладками →
  [оглавление | документ | миникарта] → статус-бар (слов, время чтения) внизу.
- Темы: тёмная и светлая палитры MarkMello (фон/текст/акцент/разделители);
  читалка — «дух 1 в 1», без пиксель-в-пиксель (egui даёт свою фактуру).
- Статус-бар: количество слов и «чтение: N мин» (по 220 сл/мин), как у MarkMello.
- Сегментированные плашки вместо `<select>` — правило проекта соблюдено by design.

## 6. Архитектура и структура кода

Правила проекта: один инструмент — одна папка; модуль желательно ≤ 400 строк;
DRY; без CDN; временные файлы и тесты — в `temp/` внутри проекта.

```
darktech-md-reader/
├── Cargo.toml            # workspace не нужен; features: svg, syntax
├── .cargo/config.toml    # +crt-static, target win-x64
├── assets/fonts/         # встроенные шрифты + LICENSE
├── assets/icon.ico
├── src/
│   ├── main.rs           # CLI-пути, запуск eframe
│   ├── app.rs            # App/TabState, топ-уровень UI, хоткеи
│   ├── md/
│   │   ├── blocks.rs     # модель блоков + span'ы (bold/link/code…)
│   │   ├── parser.rs     # pulldown-cmark → blocks (стримингово)
│   │   └── anchors.rs    # якоря заголовков, outline-модель
│   ├── layout/
│   │   ├── measure.rs    # блок → Galley, оценка высот, кэш ключей
│   │   └── cache.rs      # LRU galley-кэш + карта накопленных высот
│   ├── view/
│   │   ├── doc_view.rs   # виртуальный скролл (сердце производительности)
│   │   ├── render_block.rs # отрисовка блока: текст/код/таблица/картинка
│   │   ├── minimap.rs    # скелет + вьюпорт
│   │   ├── outline.rs
│   │   ├── find_bar.rs
│   │   ├── settings_panel.rs
│   │   ├── tabs.rs
│   │   ├── welcome.rs
│   │   └── themes.rs     # палитры, типографика из настроек
│   ├── settings/
│   │   ├── model.rs      # serde-модель + normalize (clamps как в MarkMello)
│   │   └── store.rs      # %APPDATA%/DarkTechMD/settings.json, атомарная запись
│   ├── img_store.rs      # локальные картинки: decode в фоне, LRU текстур
│   ├── search.rs         # фоновый инкрементальный поиск
│   ├── watcher.rs        # notify + debounce
│   └── i18n.rs
├── tests/
│   ├── parse_golden.rs   # golden-тесты парсера (фикстуры .md → блоки)
│   └── perf_smoke.rs     # генератор файлов 1/10/50 МБ; бюджет: parse+первый
│                         # экран 50 МБ < 1 c; память < 400 МБ
└── temp/                 # генерация тестовых больших .md (gitignored)
```

Поток данных: `parser (фоновый) → blocks (Arc, иммутабельный) → doc_view
(выборка видимых) → measure/cache → render`. Изменение настроек типографики
инвалидирует кэш, но НЕ перечитывает файл.

## 7. Бюджеты производительности (критерии приёмки)

| Сценарий | Бюджет |
|---|---|
| Старт exe → окно | < 100 мс |
| Открытие 1 МБ md → первый экран | < 100 мс |
| Открытие 50 МБ md → первый экран (стриминг) | < 1 с |
| Кадр скролла (50 МБ документ) | без кадров > 16 мс после прогрева; разовые < 50 мс при вхождении в неизмеренную зону |
| Память на 50 МБ документ | < 400 МБ |
| Поиск по 50 МБ | первый результат < 300 мс, полный подсчёт в фоне |
| Изменение размера шрифта | переразметка видимого < 50 мс, фон остальное |

Методика: `perf_smoke.rs` + ручной прогон на сгенерированных файлах
(`temp/gen_big_md.py` — lorem-ipsum markdown с таблицами/кодом/заголовками).

## 8. Этапы (каждый — самостоятельный, проверяемый результат)

0. **Каркас.** eframe-окно, тема, CLI/drag-drop, парсер → блоки, наивный рендер
   всего (без виртуализации). Уже можно читать небольшие файлы. Мерж-точка: ревью модели блоков.
1. **Виртуализация.** doc_view + кэш galley + оценки высот + плавный скролл.
   Приёмка: 10 МБ без фризов. *Самый ответственный этап — делать вдумчиво.*
2. **Типографика и настройки.** Все опции из §4.9, панель настроек, persistence,
   RU/EN. Приёмка: чек-лист опций 1 в 1.
3. **Навигация.** Оглавление + миникарта-скелет + якоря + статус-бар.
4. **Мышь.** Выделение (мышь/двойной/тройной), копирование, ссылки, контекст-меню.
5. **Поиск.** Ctrl+F, подсветка, навигация по попаданиям.
6. **Вкладки, сессия, watcher, welcome.**
7. **Полировка и релиз.** Иконка/версия/метаданные, статический CRT, один exe,
   perf-тесты по бюджетам §7, README (сборка: `cargo build --release`).

После этапа 7 — сравнение с MarkMello на реальных файлах владельца.

## 9. Риски и открытые вопросы

| Риск | План Б |
|---|---|
| egui не поддерживает межбуквенный интервал нативно (LetterSpacing) | Опция работает через посимвольную раскладку только при значении > 0 (дорогой путь, включён явно); если медленно — опцию пометить экспериментальной/убрать |
| Подсветка кода syntect тормозит на гигантских блоках | Подсветка только видимых строк, кэш по блоку; feature `syntax=off` |
| Таблицы очень широкие/длинные | Горизонтальный скролл внутри блока; измерение колонок только видимых строк |
| Оценки высот прыгают при скролле | Сглаживание: коррекция скролл-позиции пропорционально доле контента выше вьюпорта (компенсация «прилипания») |
| Выделение через много блоков усложняет hit-тест | Диапазон (block, range) + маппинг к source offsets через span-карту парсера — заложено в модель блоков с этапа 0 |
| Кириллица в системной теме egui | Все шрифты встроены, egui-дефолты отключаем |
| SVG-картинки | feature `svg` (usvg+tiny-skia); если тяжело — отключаемая |

Открытые вопросы (решить до/во время этапа 0):
- Нужна ли подсветка синтаксиса в v1 (feature on/off — дефолт?) — предложение: **on**.
- Кнопка «ассоциировать .md с DarkTechMD» (запись в HKCU, без установщика) —
  предложение: добавить в этап 7 как опциональную кнопку в настройках, off по умолчанию.
- Оглавление: сворачивание веток как в MarkMello есть? В v1 — без сворачивания
  (только макс. уровень), сворачивание — v1.1 если захочется.
